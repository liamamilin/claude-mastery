# 12｜真实验证标准，防止教材“讲得很好却跑不通”

## 三层状态必须区分

1. **已写**：文件确实存在，内容完整。
2. **已执行**：操作确实在明确环境发生，记录命令、版本、结果。
3. **已通过读者验收**：一个不借助隐藏前置知识的人照正文操作，得到了预期行为。

不得把“已写”标成“已通过”，也不得把脚手架存在说成案例完成。

## 单章最小证据

- 起点：截图/目录/版本、所需软件、权限。
- 读者行动：具体哪个界面发什么指令、执行什么命令。
- 产物：路径 + 文件变化/网页/测试结果，和本章目标一致。
- 异常分支：至少一条真正可能出现的分支，以及如何查证，不是“重试几次”。
- 学习检查：无需人工评分服务器也能自我观察结果。

## 测试矩阵

| 产物 | 静态检查 | 实际操作 | 知识检查 |
|---|---|---|---|
| 章节正文 | 路径与导航、错别字、Markdown 结构 | 读者能跟做，链接可点 | 术语与操作范围准确 |
| 案例 A | JS语法、无远程依赖 | 新增/刷新/删除/空输入 | 本地存储的含义 |
| 案例 D | JS语法，但故意保持有 bug | “删除消失→刷新重现”可重复，修复版本刷新后不重现 | 能推导出持久化缺陷 |
| VitePress 站点 | npm build + 资源检查 | 桌面/手机首页、章节、搜索、练习 | 学习路线清楚，已完成/规划中明确 |
| GitHub Pages | workflow/YAML/路径 | 线上部署后访问资源与深链接 | 无需自建后端 |
| PDF/EPUB | 文件存在、打开无错误 | 阅读目录/中文/代码/图片 | 正文与站点一致 |

## 实际排查循环

```text
重现现象
→ 陈述已知事实
→ 给出 1-3 个可区分的假设
→ 做最小验证动作
→ 根据证据选修复/撤销/换方案
→ 回归检查原有能力
```

不得将“让模型再自查一次”视为证据。若三次尝试没有更多信息，应主动检查假设和输入条件，不能持续堆叠测试门禁或重复改同一块代码。

## 时间与额度

- 只在可独立完成且有收益的任务上使用子代理并行，不为证明“高级”而强制多 Agent。
- 首个迭代必须产出真实正文、一个案例和可操作网站，不允许先花大量调用创建管理模板工厂。
- 图像/外部 API 服务需用户授权、明确可能成本。没授权时依然能靠 SVG/CSS/真实截图完成精美网站。

## 最简交付报告

每个阶段只需要写：新增的实物文件、运行过什么、结果如何、遇到什么障碍、下一步是什么。把记录写进 `STATUS.md`，而不是另起大型审核系统。
