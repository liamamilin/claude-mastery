# 01｜为什么写《驾驭 Claude》

## 定位

**《驾驭 Claude：Claude Code Desktop 从基础使用到复杂任务掌控》** 是一套中文实战教材，同时是可在 GitHub Pages 访问的互动学习网站（Claude Mastery Lab）。

它不是 Anthropic 官方手册的中文翻译，不是快捷键百科，也不单纯是提示词合集。

### 总终点

面对未见过的工作，读者能够：

1. 判断这是一个目标明确的实现任务，还是需要先探索与查证；
2. 在 Claude Desktop 的 **Code** 标签页中准备正确的项目、工作环境、权限和上下文；
3. 选择直接执行、Plan、小样验证、分阶段推进或分工协作；
4. 观察实际文件、差异、命令和运行行为，而不仅看 Claude 的总结；
5. 遇到错误、偏离和连续失败时辨认是需求、环境、依赖、实现还是验证的问题；
6. 必要时停止、回退、缩小范围或改变假设，而不是让 Claude 无限打补丁；
7. 保存工程状态，跨会话持续推进，最终交付可复用、可验证的成果。

## 双轨能力

- **控制台轨（具体工具）**：Code/Chat/Cowork 区分；Local/Cloud/SSH；项目文件；提示区；附件；模型/权限；集成终端；预览；diff；Git/worktree；CLAUDE.md；Skills/Connectors/MCP/Plugins/Hooks/subagents；云与远程。CLI 只在 Desktop 不便操作或需要跨端迁移时引入。
- **主导轨（可迁移能力）**：明确结果、收集证据、组织任务、控制自主性、验证行为、推翻错误假设、协调并行工作、保存上下文、选择投入/止损。

不能让工具轨挤掉主导轨。真正学会驾驭 Claude，应可以从本书迁移到陌生项目。

## 目标读者

- 零基础但有项目想法的人：早期章节必须解释“文件夹、运行、终端、Git、浏览器预览”的必要含义，不预设有编程经验。
- 已会软件开发但希望提高 Agent 生产力的人：后半段聚焦分工、上下文、审查、复杂项目。
- 项目/内容创作者：不仅是写代码，也能让 Claude 帮助组织工程化的调研、网页和数据工作，但不混淆 Code 与 Cowork 的职责。

## 书的承诺与非承诺

- 承诺：操作具有起点、可重复的步骤、可观察的结果和失败分支。
- 不承诺：不同模型每次生成同一代码；所有账号拥有同一功能；“让 Claude 一句话做出所有产品”。
- 网站上的训练交互为**模拟练习**；真实 Claude Code 执行发生在读者本机或授权环境，不在 GitHub Pages 服务器上运行。

## 学习完成证明

不是“读完32章”。最终毕业题必须让读者在未知现有项目上：先调查 → 定义可检验目标 → 选执行策略 → 完成至少一个可运行修改 → 处理一处意外 → 提交证据 → 保存可接续状态。

评估标准以证据为主：可复现行为、失败时的判断、对未验证范围的坦诚说明。
