# 03｜跨章节能力地图

课程学习的对象不是按钮，而是从零到结果的闭环：

```text
意图不清 / 目标明确
        ↓
发现现实约束（环境、权限、仓库、依赖、事实）
        ↓
决定路线（探索 / 计划 / 小样 / 直接实施）
        ↓
执行（Claude Code Desktop 会话、工具、文件操作）
        ↓
核对（可观察行为、测试、diff、截图、日志）
        ↓
判断（够了 / 修复 / 换路线 / 回退 / 缩小范围）
        ↓
留下可接续成果（源文件、版本、状态、说明）
```

| 能力 | 初学者行为 | 进阶者行为 | 对应章节 | 案例 |
|---|---|---|---|---|
| 理解能力边界 | 分清聊天与改文件 | 知道当前端、权限和工具的限制 | 01-04 | A |
| 目标导出 | 把模糊需求拆成尝试方向 | 设计可验证的中间成果 | 05-08 | A/F |
| 取证调查 | 指明相关文件和截图 | 识别事实、假设与缺失证据 | 09-12 | B/D |
| 执行控制 | 选择权限和观察变更 | 阶段推进、Worktree 隔离与合并 | 13-16 | B |
| 完成验证 | 自己点击运行的页面 | 自动化检查、边界测试、审查报告 | 17-20 | A/C |
| 失误纠偏 | 复现、看日志 | 识别根因、改变假设、回退止损 | 21-24 | D |
| 可复用扩展 | 使用一个 Skill | 判断 MCP/插件/Hook/代理的投入产出 | 25-28 | E |
| 长期协作 | 保存状态，下次继续 | 组织跨会话、多场景的项目与交付 | 29-32 | F |

## 高阶能力的特别测试

1. Claude 提议搭一个复杂架构，但需求只有一个页面：读者能否要求先做一页最小可运行版本？
2. Claude 连续三次修按钮失败：读者能否要求先查状态流转与数据持久化？
3. 多会话同时改同一文件：读者能否隔离修改、辨识冲突与保留正确版本？
4. 某能力因订阅或环境不可用：读者能否选择完成同等学习目标的替代路线？
5. 自动测试通过但 UI 不可用：读者能否补真实用户行为验收？

## 最终评分（100分）

- 定义可验证结果20分；调查事实和环境15分；执行策略15分；实际作品与代码20分；测试与纠偏20分；接续交付10分。没有可运行成果或故障无法复现，不能仅凭描述给满分。
