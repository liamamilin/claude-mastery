# 10｜互动训练场：让读者练习决策，不只是点按钮

交互练习应当比动画更有教育价值。全部纯前端，状态存在 Vue 客户端，不调用 Claude API、不上传数据、不执行读者机器上的命令。

## 优先开发 3 个互动模块

### Lab 1：诊断分支（已提供组件雏形）

场景：一个收藏网站里点击“删除”后屏幕消失，刷新页面又出现；Claude 已经反复改按钮两次。

备选路径：

- A. 再调按钮视觉和触摸区域：有可能改善 UI，但无法解释刷新后的数据恢复。
- B. 追踪删除动作与持久化写入：最有信息价值，可以区分“只改屏幕”和“真正删存储”。
- C. 立刻推倒全部代码重写：代价大，尚无足够证据。

**反馈**：每个选项解释它能得到什么信息、遗漏了什么、下一步行动；正确路径不是“永远只查 localStorage”，而是针对**可观察症状**提出和验证假设。

### Lab 2：执行方式选择器

输入（组合选择）：需求是否明确、关键技术是否未知、是否有稳定的验收方式、是否出现连续失败。

输出：建议“先探索 / 做小样 / 直接执行 / 先调查根因 / 暂停重新审视目标”，给适用条件和**可复制到 Desktop Code 的示例说明**。可切换输入并即时更新；不是一句套话。

### Lab 3：读者自验清单

用可选 checklist 显示案例关键观察点：项目成功启动、完成一个功能动作、刷新后结果一致、检查 diff、保留版本。保存状态时明确标注“**这是读者自报，不是自动测试**”。允许清空本地记录。

## 课程其他可选练习

- “哪个材料最能定位问题？”：比较报错日志、截图、无关文件的证据价值。
- “工作树该怎么开？”：判断适合串行还是并行。
- “CLAUDE.md/Skill/Hook/MCP 怎么选？”：按重复程度和任务性质作出取舍。
- “GitHub Pages base 修复”：面对项目页资源404，选择最小排查动作。

## 审核每个互动模块的清单

1. 读者能明白场景、可选动作和目标，不需在页面外寻找关键题干。
2. 每个选项至少有一段**区别于其他选项**的解释。
3. 有继续/重置，键盘 Enter/Space 与触控均可操作。
4. 没有服务器或外部 API 也能加载。
5. 即使 JS 不可用，正文中也有对应的原则说明。
6. 不伪造读者已掌握或真实实验已通过。

## 毕业题交付格式

读者提交：

```text
result/
  goal.md               # 目标、非目标、可观察验收
  findings.md           # 环境与现状调查，事实与假设分开
  working-project/      # 代码与运行说明
  validation.md         # 运行/测试/截图/未覆盖范围
  recovery.md           # 一次失败如何处理、是否回退
  handoff.md            # 下一会话怎么继续
```

评价优先看真实成果和取证思路，不要求模型生成的代码与样本答案逐字相同。
