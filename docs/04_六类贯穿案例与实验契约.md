# 04｜六类贯穿案例：让学习不只是记住命令

案例必须有 `README.md`、起点（可复制/可运行）、操作步骤、真实验收、常见失败分支、测试或人工核验记录。当前本包只为 **A 和 D** 提供了初始可运行源码，其余属于开发任务，**不能标记为已验证**。

## 案例 A｜LinkShelf：从一句话到收藏工具

**用户故事**：收藏一个网址及标题，能够查看、删除、刷新后仍存在。进阶加入标签、搜索、导出。

- 入门环境：本地浏览器可直接打开 `cases/lab-a-links/index.html`；无远程 API、无登录，数据只存浏览器 `localStorage`。
- Desktop 操作：在 Code 标签页打开项目文件夹 → 让 Claude 解释已有文件 → 请求增加搜索 → 观察 diff → 浏览器验证。
- 第一步可见结果：新增项目后列表增加，刷新页面后依旧存在。
- 验收动作：新增 → 刷新 → 删除 → 刷新；检查空标题和非法 URL 的反馈。
- 教学陷阱：有时 `file://` 本地存储在不同浏览器/配置下有限制；若遇到限制，使用本地静态服务预览，并记录实际 URL。不要在书里无条件宣称 file:// 跨浏览器可靠。
- 扩展：搜索、标签、JSON 下载及导入恢复。

## 案例 B｜陌生仓库 IssueBoard：读懂再修改

- 由 Claude 创建一个小仓库（静态任务看板或 Node web 项目），提供清楚的历史文件，故意保留一处有解释价值的边界问题。
- 学生只能看到需求：“给任务增加优先级过滤”；先让 Claude 找入口、运行与数据结构，写事实简报，再修改。
- 引入 Git、diff、commit、worktree、会话续写，避免直接上复杂 CI。
- 验收：旧功能保持正常、优先级筛选工作、有变更记录、无无关文件被改动。

## 案例 C｜Web Preview Lab：让桌面版真正验证网页

- 创建数据卡片、筛选控件和响应式布局的纯静态仪表板，可用 Vite 或 VitePress 演示。
- Desktop Code 的 Browser/Preview 面板查看应用，尝试不同屏幕尺寸、点击按钮与检查错误日志。
- 验收：空数据、错误数据、移动端都能给合理反馈；至少一张**来自真实运行**的界面截图。
- 延伸：构建与 GitHub Pages 发布，说明本地 dev server 并非线上必须运行的服务器。

## 案例 D｜Persistence Detective：停止反复打补丁

- 已附 `cases/lab-d-persistence/`。刻意错误：点击“删除”会更新屏幕，却**没有把删除后的数据写回 localStorage**，刷新又出现。
- 操作约束：先实际复现，记录屏幕变化；让 Claude 写出“已知 / 假设 / 最小判别实验”；查状态存储路径再修复。
- 提供 `solution/app.js` 供教师核对，学员做实验时不提前打开答案。***这是教学刻意设计的故障，不代表全包代码质量不合格。***
- 可交互网站中的模拟决策不代替在本地打开故障案例。

## 案例 E｜能力扩展包：从一次经验到可复用工作

- 第25章：以教案审阅流程做一个项目 Skill（例：术语检查/练习验证），其内容必须真的被调用或载入。
- 第26章：用可授权/离线的连接器数据源演示 MCP；无凭据时提供最小本地演示，不强制用户申请第三方服务。
- 第27章：为已经证明稳定的任务做一个小 Hook（例如编辑后格式检查），不要把所有工作都自动化。
- 第28章：将一个独立调查交给子代理，比较与直接主会话做的收益、额外使用量和整合质量。

## 案例 F｜毕业题：未知项目与不完整需求

创建一个**未在前文逐步示范**的简短练习仓库（例如本地阅读记录器），给读者目标和初始材料，不直接给解决路径。

毕业产物：事实调查、可验证的目标、方案取舍、运行代码、一次故障诊断、验证记录、可回退版本与接续文件。答案必须留有多条合理路径，不能要求模型输出固定措辞。
