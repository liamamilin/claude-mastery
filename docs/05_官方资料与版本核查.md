## Desktop 特性核对卡

| 书中表述 | 写作时怎么处理 |
|---|---|
| Desktop 的 Code 标签页是开发主场 | 确认当前 UI 并截图；不要把 Cowork 的选项误认为 Code 的选项 |
| Git worktree 供并行隔离 | 仅在 Git 项目内演示；创建前确认开关位置及默认值；归档前保留未提交修改 |
| Browser pane 可预览、自动验证 | 以当前 Desktop 版和本地会话实验为准；SSH / 云端可能存在浏览器访问差异 |
| 模型选择与 permission mode | 操作界面与计划/组织策略相关；在本章写出最小例子和不可用分支 |
| `.claude/launch.json` 用于预览 | 验证项目根目录与服务器端口；示例不能放进用户密钥 |
| Desktop 与 CLI 不是同一会话列表 | 可共享一部分指引和配置，但不要声称全部会话自动同步；官方指出内嵌 Code 版本可不同于独立 CLI |
| Claude Design 或 Computer use | 属于依版本、计划、地区、权限的进阶选项；始终提供纯 SVG/CSS/浏览器的替代路线 |
| GitHub PR 检查 | 某些操作需要 `gh` 和 GitHub 登录；没有授权不得把该步骤作为必做前置 |

## 写正文前的事实核对动作

1. 检查官方当前说明（链接、访问日期、适用平台/计划）。
2. 在本地 Claude Desktop **Code** 标签页亲自观察：菜单名称、按钮、使用限制与版本；必要时记录 `/status` 或“About Claude”输出。
3. 如果截图和文稿说明不一致，以当前可验证操作修改文稿、截图与说明；不要制作“看似真实”的 UI 图片。
4. 命令必须区分 CLI vs Desktop 提示区命令 vs 终端 shell 命令 vs 本书网站按钮。
5. 为难以普适的操作提供“我没有这个入口怎么办”：说明替代路径、跳过方式和差异，不虚构按钮。

## 建议的事实注记格式

> 已在 2026-10-26 的官方 Desktop 参考中核对；实际步骤以你的 Claude Desktop 版本为准。如按钮不一致，请在设置中检查版本，再查阅官方链接。

案例截图图注建议：`Claude Desktop Code（macOS，实际版本号 YYYY；日期），截图取自真实本机运行，已遮蔽账号/隐私信息。`

## 禁止的假验证

- 没有真正登录但写“点击已成功”。
- 项目网页只看到了静态图就写“交互通过”。
- 将 Claude 生成的模拟终端界面当真实截图。
- 不同订阅/环境的能力未经确认就统一写成所有读者可用。
