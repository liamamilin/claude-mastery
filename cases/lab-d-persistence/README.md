# Lab D｜停止补丁：持久化缺陷诊断现场

此案例是**故意带有一个 bug 的教学实验**，请不要在制作资料包时将 bug 修掉。目标是训练读者发现“屏幕状态与存储状态不同”的根因。

## 实际复现

1. 在同一浏览器来源下打开 `index.html`（必要时用 `python3 -m http.server 48128`）。
2. 页面初始有一条“故障排查实验”任务；如果旧存储残留，点击“恢复练习初始状态”按钮。
3. 点击删除：任务立即消失。
4. 刷新：任务又出现。
5. 对照 `app.js`，找到 `removeTask()` 只执行了 `render()`，没有调用 `persist()`。
6. **教师用参考**在 `solution/app.js`；学员应先独立调查后再查看。

## Desktop Code 的调查提示

> 请先复现并解释 “删除后刷新又出现”，暂不修改代码。只说你确实在源码中发现的事实与仍需验证的假设；指出删除后与刷新时的数据路径，然后提出最小修复。

## 验收

修复版应当：新增→刷新后保留；删除→刷新后不回来；恢复初始练习后能重新进行。不能只看删除后立即消失。

如果 file:// 存储策略导致初始测试不稳定，请使用 localhost 服务器并一直使用同一个端口和 URL 来源地址。不同端口视为不同 origin。
