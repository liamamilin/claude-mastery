# 第 17 章｜桌面浏览器预览与自动验证

> 本章终点：你用 Browser 窗格对 Lab C 做一次完整的“看、点、换尺寸、查错误”检查，**发现一个只有窄屏才出现的真实缺陷**；你能区分 Claude 自己用浏览器验证到的与它没有验证到的，并写出自己补充的验收。

## 1. 代码看起来对，页面却是坏的

写网页最常见的错觉是：代码读起来没问题，所以页面没问题。可浏览器才是最终的裁判——布局、点击反应、窄屏表现、控制台错误，都只在**运行**时才暴露。

Desktop 的 Browser 窗格让这件事发生在工作区内部。官方参考（2026-10-26）里与本章相关的要点：

- 打开：`Cmd+Shift+B`（macOS）/ `Ctrl+Shift+B`（Windows），或点标题栏 **Browser**；
- 窗格头部 **Dev servers** 菜单启动、停止 `.claude/launch.json` 里配置的服务器；
- **⋮** 菜单里有 **Auto-verify changes**（`autoVerify` 默认开启）、**Keep cookies**、**Clear browsing data** 等；
- Claude 可以查看运行中的应用、测试接口、查看日志并据此迭代；它也能打开外部网站，但**对外部网站的操作会先请求你的许可**（**Allow once / Always allow / Deny**）；
- Browser 使用干净的配置文件，没有你保存的登录状态；
- SSH 会话里 Claude 无法使用 Browser 窗格的工具（官方说明）。

> **能力边界：** 自动验证的价值取决于 Claude 实际做了什么。**它说“我验证过了”时，要追问：用什么尺寸？点了哪些按钮？看了哪些状态？**

## 2. 案例 C：学习进度看板

资料包的 `cases/lab-c-preview/` 是一个纯静态页面：六张进度卡片、按状态筛选、空数据与加载失败状态。**请先不要读 `README.md` 和 `solution/`**，它们含有答案。

把 `cases/lab-c-preview` 复制为 `lab-c`，用第 4 章的方法配置并启动预览服务（端口自选，作者用 48127）。

## 3. 第一遍：桌面宽度，按预期点一遍

在 Browser 窗格里打开页面，逐条检查：

| 动作 | 应看到 |
|---|---|
| 页面加载 | 标题“学习进度看板”，状态行“显示 6 / 6 项”，6 张卡片 |
| 点“进行中” | 2 张 |
| 点“已完成” | 1 张 |
| 点“未开始” | 3 张 |
| 网址后加 `?empty=1` | “暂无数据。” |
| 网址后加 `?error=1` | “数据加载失败：模拟的加载失败” |

**作者实测（2026-10-26，Browser 窗格）：** 以上数字与文字全部一致。

到这一步，一个只看功能的验收会说“通过”。**但我们还没换尺寸。**

## 4. 第二遍：换成手机宽度

Desktop 的 Browser 窗格支持调整视口。如果你找不到该控件，也可以用普通浏览器的开发者工具里的设备模拟，或者直接把窗格拖窄——**记录你用了哪种方式**。

在 375 像素宽度下：

- 页面能不能完整看到？
- 有没有横向滚动条？
- 卡片是不是被截断？

### 作者的实测

在一个 375px 宽的 iframe 中加载同一页面，量得：

- 起始版本：`document.documentElement.scrollWidth` 是 **1016**，远大于 375 → **横向溢出**，第二列卡片被截断；
- 网格样式是 `320px 320px 320px`（固定列宽）。

![同一页面在 375px 宽度下的真实渲染：左为起始版本，右为修复后版本。左侧右边缘的卡片被截断。](/screenshots/lab-c-mobile-compare.png)

*图：Lab C 在 375px 宽 iframe 中的真实渲染，使用无头 Chrome 拍摄，2026-10-26。右为 `solution/` 参考修复。这不是 Claude Desktop 界面截图。*

**这就是“代码看着对、页面是坏的”：** 功能（筛选、空状态、错误状态）全部正确，缺陷是 CSS 里固定的 `repeat(3, 320px)`。读代码也许能发现，但**一次窄屏预览比一份代码审阅更便宜、更确定**。

## 5. 让 Claude 修复，并规定验证方式

**发送到 [Desktop Code] 的提示框（Manual）：**

> 在 375 像素宽度下，页面出现横向滚动，右侧卡片被截断。请修复，使窄屏下单列显示、没有横向滚动，宽屏仍是多列。只改 `styles.css`。
>
> 完成后请在浏览器里**分别在 375 像素和 1100 像素宽度**检查，并报告每个宽度下 `document.documentElement.scrollWidth` 与窗口宽度是否相等。

最后一句把“验证”写进了任务，而且给了**可核对的数值**。

### 你要核对什么

1. diff：只改了 `styles.css`；网格列定义不再是固定像素；
2. 自己的眼睛：375 宽度下无横向滚动、卡片完整；1100 宽度下仍多列；
3. 回归：筛选、`?empty=1`、`?error=1` 仍然正确。

参考修复（`solution/styles.css`）用的是 `repeat(auto-fill, minmax(min(100%, 260px), 1fr))`，并让筛选按钮可以换行。作者实测：375px 下 `scrollWidth` 为 375，网格只有一列 327px。`solution/` 的 `app.js`、`index.html`、`data.js` 与起始版本逐字节相同（`cmp` 确认），只有 `styles.css` 不同，所以筛选、空状态、错误状态的逻辑与第 3 节实测一致。你的修复可以不同，**标准是行为，不是代码一致**。

## 6. 控制台与日志

页面看起来对，也可能在控制台悄悄报错。打开浏览器的开发者控制台，刷新并操作一轮，**记录有没有红色错误**。作者在本章对应的实测中没有看到控制台错误。

> 如果 Claude 说“页面没有报错”，让它说明**是从哪里读到的**——读的是服务端日志，还是浏览器控制台？两者不是一回事。

## 7. 失败分支：预览与真实不一致

- **预览是旧的**：浏览器缓存或服务根目录不对；让 Claude 报告被改文件的完整路径与服务根目录；
- **端口占用**：预览服务启动失败；换端口，同时改 `launch.json` 的 `runtimeArgs` 与 `port`；
- **Claude 声称已验证，你复查发现没有**：把它的验证步骤逐条列出来，缺哪一步就要它补哪一步。**不要因为它说了“已测试”就省略自己的那一遍。**

## 8. 独立练习

自己做一次“能力边界清单”：对 Lab C，列出 Claude 能用 Browser 窗格自动验证的 3 件事，和**必须由你亲自**判断的 3 件事（提示：“好不好看”“语气是否合适”“这套配色是否符合品牌”）。
