# 第 11 章｜CLAUDE.md、规则与记忆怎样分工

> 本章终点：你为 Lab B 写出一份**不到 20 行**的 `CLAUDE.md`，只放 Claude 无法自己推断的事实；你能说出 CLAUDE.md、自动记忆、规则文件、会话上下文四者各管什么，并用一次新会话检验它们是否真的生效。

## 1. 问题：每次都要重新交代

第 9 章你花了一轮调查才知道 Lab B 要用 `python3 -m http.server` 才能运行。如果明天新开一个会话，Claude 对这些一无所知——**每个会话都从一个全新的上下文窗口开始**。官方文档把这件事讲得很直白，并给出两种跨会话携带知识的机制：

| | CLAUDE.md | 自动记忆（auto memory） |
|---|---|---|
| 谁写 | **你** | **Claude** 自己 |
| 内容 | 指令与规则 | 它从你的纠正和偏好中学到的东西 |
| 范围 | 项目、用户或组织 | 每个代码仓库一份 |
| 载入 | 每个会话 | 每个会话（只载入前 200 行或 25KB） |

两者都是**上下文，不是强制配置**。官方明确写道：要无论 Claude 怎么决定都阻止某个动作，应该用 hook（第 27 章），而不是指望一句指令。

## 2. CLAUDE.md 放在哪里

按官方文档，CLAUDE.md 可以放在多个位置，作用范围不同：

| 范围 | 位置 | 谁看到 |
|---|---|---|
| 用户 | `~/.claude/CLAUDE.md` | 只有你（所有项目） |
| 项目 | `./CLAUDE.md` 或 `./.claude/CLAUDE.md` | 通过版本控制共享给团队 |
| 本地 | `./CLAUDE.local.md` | 只有你（当前项目）；官方建议加入 `.gitignore` |
| 组织 | 由 IT/管理员部署（各系统路径不同） | 组织内所有人 |

加载规则的要点：当前目录**以及它上面所有目录**里的 `CLAUDE.md` 在启动时都会被载入，并**拼接**在一起而不是互相覆盖；子目录里的 `CLAUDE.md` 在 Claude 读写那个子目录文件时才按需载入。离你工作目录越近的内容放在越后面，所以被最后读到。

官方还说明，如果仓库已经有 `AGENTS.md`（为其他代码代理准备的文件）而没有 `CLAUDE.md`，Claude Code 可以直接读取它。本书不假设你有这类文件。

## 3. 写什么，不写什么

官方最佳实践给了一条非常实用的判断：**对每一行问——删掉它会让 Claude 犯错吗？** 不会就删。

| 该写 | 不该写 |
|---|---|
| Claude 猜不到的命令（如“用 `python3 -m http.server` 才能运行”） | 读代码就能看出来的事 |
| 与默认习惯不同的风格规则 | 语言的标准约定 |
| 测试方式、首选测试命令 | 冗长的 API 文档（改为放链接） |
| 本项目特有的架构决定 | 经常变化的信息 |
| 容易踩的坑（如“旧数据缺 `priority` 字段”） | “写干净的代码”这类不言自明的话 |

官方给的体量建议是：**每个 CLAUDE.md 目标在 200 行以内**；过长会占用更多上下文，并降低遵守率。如果 Claude 总是忽略某条规则，常见原因是文件太长，规则被淹没了。

## 4. 动手：为 Lab B 写一份短 CLAUDE.md

### 4.1 用 `/init` 起草，然后审阅

**[Desktop Code]** 在 `lab-b` 会话的提示框输入：

```text
/init
```

官方说明：`/init` 会分析代码库，生成包含构建命令、测试指令和它发现的约定的起始 CLAUDE.md；如果已存在，会建议改进而不是覆盖。

**重要：它只是草稿。** 请逐行审阅，删掉三类内容：①能从代码直接读出的描述；②你不确定是否正确的“推测”；③冗长的目录说明。

### 4.2 一份可用的版本（参考）

最后留下来的，应该接近这样（根据第 9、10 章你已经**亲自验证过**的事实）：

```markdown
# IssueBoard（Lab B）

## 运行与测试
- 必须用本地 http 服务运行，不要双击 index.html：`python3 -m http.server 48125 --bind 127.0.0.1`，访问 http://localhost:48125/
- 逻辑测试：`node test.mjs`（只覆盖分组与计数，不覆盖页面）

## 数据约定
- 数据在 `data/issues.json`。没有 `priority` 字段的旧任务按“普通”处理。
- 不要修改 `data/issues.json`，除非任务明确要求。

## 完成标准
- 修改后必须在浏览器里确认：页面显示 5 个任务、三列数量正确。
```

注意它的特点：

- 每一条都是你**验证过**的事实或一个明确的规则；
- 没有“代码要整洁”这类空话；
- 约 12 行。

让 Claude 创建：

> 请把下面的内容写入当前目录的 `CLAUDE.md`，原样写入，不要添加别的内容：（粘贴上面的 Markdown）

### 4.3 用 `@` 引入长文档，而不是复制进去

CLAUDE.md 支持 `@路径` 语法导入其他文件，路径相对于**包含该导入的文件**；导入有最多四层的递归限制。官方特别提醒：导入的文件会和 CLAUDE.md 一起载入，**并不减少上下文开销**——它只是帮你整理。如果你想在 CLAUDE.md 里提到某个路径而不导入它，用反引号包起来。

## 5. 检验：新会话真的知道吗？

写了不等于生效。检验方法：

1. 关闭当前会话，**新建**一个会话，目录仍是 `lab-b`。
2. 先不要给任何背景，直接问：

   > 我想看看这个项目的页面。应该怎么运行？

3. 观察：Claude 是否给出了 CLAUDE.md 里的命令？如果不是，在提示框运行 `/context`（官方说明可查看上下文使用情况）或 `/memory`（列出 CLAUDE.md 等记忆文件）确认文件是否被载入。

**这就是“规则有没有真的起作用”的实验。** 如果它没引用你的规则，不是你写得不对，就是文件没被加载——两者要分开排查。

## 6. 规则文件：给一部分文件的规则

当项目变大，把所有规则塞进一个文件会拖慢整体遵守率。官方提供 `.claude/rules/` 目录：把一个主题写成一个 `.md` 文件（如 `testing.md`），并可以通过 `paths` 字段限定只在 Claude 处理匹配的文件时才载入。这样“前端规则”不会在你改后端时占用上下文。

Lab B 只有几个文件，**不需要**这一层。判断标准：只有当 CLAUDE.md 超过 200 行，或不同部分的规则确实互不相干时，才拆分。

## 7. 自动记忆：Claude 自己记的笔记

官方说明：自动记忆让 Claude 在工作中积累知识，**不需要你写**，例如它从你的纠正里学到“这个项目用 pnpm，不用 npm”。要点：

- 在本地会话中默认开启；可用 `/memory` 里的开关关闭；
- 存放在 `~/.claude/projects/<项目>/memory/`，同一个 Git 仓库的所有工作树与子目录共用一份；
- **只在本机有效**，不会跨机器或云端环境同步；
- 是普通 Markdown，你可以随时查看、编辑或删除（`/memory` 可以浏览）；
- 如果你对 Claude 说“记住……”，它会存到自动记忆；要写进 CLAUDE.md，必须明确说“把这个加到 CLAUDE.md”。

**关键区别**：CLAUDE.md 是你**有意识地**写给项目的规则，能被团队共享；自动记忆是 Claude 的**个人笔记**，你应当偶尔打开审阅，别指望它精确。

## 8. 四者怎样分工

![四种机制按寿命与谁书写区分：会话上下文最短，CLAUDE.md 由你维护并长期有效，自动记忆由 Claude 书写且仅限本机。](/figures/memory-layers.svg)

| 机制 | 一句话 | 适合放 | 不适合放 |
|---|---|---|---|
| **会话上下文** | 当前对话与读过的文件 | 本次任务的细节 | 需要明天还记得的事 |
| **CLAUDE.md** | 你写给项目的常驻说明 | 运行命令、关键约定、坑 | 长篇文档、会变的信息 |
| **规则文件** | 分主题、可按路径限定的说明 | 仅与部分文件相关的规则 | 小项目的全部规则 |
| **自动记忆** | Claude 自己的笔记 | 你的纠正与偏好 | 必须强制执行的规定 |

> 需要**强制**的东西，既不放 CLAUDE.md 也不放记忆，交给权限规则或 hook（第 13、27 章）。

## 9. 失败分支：规则被忽略

1. 先确认已载入（`/memory`、`/context`）。
2. 文件是否过长？瘦身，把真正重要的几条放在显眼位置。
3. 有没有互相矛盾的规则？官方警告矛盾时 Claude 可能任意选一条。检查是否同时存在项目、用户与子目录的 CLAUDE.md。
4. 对**真正**不能被忽略的一条，官方建议只对那一行加强调（如 “IMPORTANT”），加太多反而没有一条突出。

## 10. 独立练习

为本书项目自己的根目录 `CLAUDE.md` 做一次“瘦身审查”：逐行问“删掉会让 Claude 犯错吗”，标出你会删的行并写出理由。再对比你对 Lab B 写的那份：哪一份更接近“只放 Claude 无法自己推断的事”？
