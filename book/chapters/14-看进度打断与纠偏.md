# 第 14 章｜看进度、打断与纠偏

> 本章终点：你能在 Claude 工作过程中分辨“正常推进”和“正在跑偏”，选择**停止**还是**不停止直接纠正**，并知道什么时候应该放弃当前会话，换一个更清楚的提示重来。

## 1. 越早纠偏越便宜

官方最佳实践里有一句话值得记住：**最好的结果来自紧密的反馈回路。** Claude 偶尔能一次做对，但及时纠偏通常能更快得到更好的解。

跑偏的成本是累积的：错误的假设会成为后续每一步的基础。第 3 步发现比第 30 步发现便宜得多。

## 2. 看什么：进度信号

任务运行时，你可以看这些：

| 信号 | 在哪里 | 提示什么 |
|---|---|---|
| 它读了哪些文件 | 对话区的操作记录 | 它的注意力在哪；有没有读不相关的 |
| 它想运行什么命令 | 对话区 / 审批提示 | 是否越界（安装、删除、联网） |
| `+N -M` 变更计数 | 会话的 **Changes** 卡片 | 改动大小是否与任务匹配 |
| 后台任务 | 标题栏 **⋮** 菜单里的 **Background tasks** | 子代理、后台命令、动态工作流各在做什么；点击条目可看输出或停止 |
| 思考过程 | `Ctrl+O` 循环 **Normal / Thinking / Verbose** | 想知道它为什么这样做时，切到更详细的视图 |

> 以上来自官方 Desktop 参考（2026-10-26）。具体显示以你的版本为准。

### 跑偏的早期征兆

- 改动行数远大于任务应有的规模（“只改标题”却 `+200`）；
- 开始读你没提过的目录；
- 提议安装依赖、新建框架；
- 同样的步骤重复出现（读文件 → 改 → 读同一个文件 → 改回去）。

## 3. 两种纠偏：停止 vs 不停止

官方给出两种方式：

**① 停止**：点击停止按钮立即中断；也可以按 **Esc** 停止 Claude 的回应。适用于：它正要做危险的事，或明显方向错了。上下文保留，你可以接着重新指示。

**② 直接更正**：输入更正并按 **Enter**。官方说明这**不会打断当前动作**，Claude 会在当前动作完成后读取你的更正。适用于：方向基本对，需要补充一个约束。

### 怎么选

| 情况 | 选 |
|---|---|
| 它正在删除/覆盖/安装不该碰的东西 | **停止** |
| 它改错了文件，已完成多步 | **停止**，再说明 |
| 你忘了说“别改样式” | **更正**（不停止） |
| 它的做法可行但不是你想要的风格 | **更正** |

## 4. 一次好的纠偏长什么样

坏的纠偏：

> “不对。”
> “再试一次。”
> “你为什么这样？”

好的纠偏包含三点：**哪里不对（指到文件或行）**、**期望是什么**、**边界在哪**。

> `app.js` 里你新增了 `lowerTitle` 字段并写入了存储，这改变了存储格式。请移除，改成在渲染时临时计算小写标题，不要写进存储。

最精确的做法是**直接在 diff 里评论**（第 4 章）：点击那一行，写评论，`Cmd+Enter`（Windows 为 `Ctrl+Enter`）一次提交全部评论，Claude 会读取并修改。

## 5. 动手：故意制造一次跑偏并纠正

### 准备

`lab-a` 新副本，Manual 模式。

### 步骤 1：发一个容易跑偏的指令

> 帮我把收藏页改得更现代一点。

这句话没有边界，是故意的。

### 步骤 2：观察并介入

批准或拒绝前，看：

- 它提议改几个文件？`+N -M` 多大？
- 它有没有想新建文件或引入外部库？

**不要接受大改动。** 拒绝，并发送带边界的更正：

> 范围太大了。只改 `styles.css`：调整主标题字号和卡片圆角。不要改 `index.html` 和 `app.js`，不引入任何外部库。

### 步骤 3：在 diff 里再纠一次

即使这次范围对了，在 diff 里找一处你不满意的小改动（比如颜色），**用行评论**让它改，而不是重新写一大段话。

### 记录

- 第一次提议的 `+N -M` 是多少？
- 你的更正之后是多少？
- 第二次纠偏用了几句话？

## 6. 什么时候该“重来”

官方最佳实践写得很明确：**如果你在同一个问题上纠正了 Claude 两次以上，上下文里已经塞满了失败的尝试**，应该用 `/clear` 开始，并写一个把教训都吸收进去的更具体的提示。一个干净的会话加更好的提示，几乎总是胜过一个纠正了很多轮的长会话。

> 这和第 8 章“先调查根因”、第 22 章“停止无效修补”是同一个信号：**连续两次失败 = 不是再试，而是换方式。**

在 Desktop 里重来的做法：新建一个会话（`Cmd+N`），把已经确认的事实写进第一条提示，或者用第 12 章的 `HANDOFF.md`。

## 7. 失败分支：它没有停下来

你按了停止，但似乎仍在执行。

1. 看操作记录，确认最后一个动作是什么——官方说停止按钮会“立即中断”，但**在按下之前已经完成的动作不会被撤销**，命令可能已经执行。
2. 用 **Background tasks** 窗格检查是否有后台命令仍在运行，必要时从那里停止。
3. 用 Changes 窗格核对磁盘上已经发生的改动，别只相信“已停止”。
4. 若已有不想要的改动：在 Manual 模式下拒绝；已应用的，用第 15 章的方法恢复。

## 8. 独立练习

找一个自己的小任务，写出**三版纠偏消息**：一版太含糊，一版太长，一版刚刚好。比较它们引起的 diff 差异（如果你实际尝试了）。至少说明“刚刚好”的那一版包含了哪三个要素。
