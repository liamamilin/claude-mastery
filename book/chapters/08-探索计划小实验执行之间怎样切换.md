# 第 08 章｜探索、计划、小实验、执行之间怎样切换

> 本章终点：面对四个不同情境，你能说出该用**探索、计划、小样还是直接执行**，并解释理由；你能在 Desktop 里切换权限模式，并知道各模式实际改变了什么。

## 1. 没有“永远正确”的流程

有人主张“一切先 Plan”，有人主张“让它直接做，错了再改”。两种说法都会在某些任务上吃亏：

- 给每个任务都加计划步骤，改一个错别字也要等一份计划——**开销大于收益**。
- 对每个任务都直接动手，遇到改动多文件、不熟悉的代码——**容易解决了错误的问题**。

官方最佳实践的说法很实用：计划在你**不确定做法**、**改动涉及多个文件**或**不熟悉代码**时最有价值；**如果你能用一句话描述这次 diff，就跳过计划**。本章把这条经验变成一套你能自己判断的决策依据。

## 2. 四个动作，四种目的

| 动作 | 目的 | 产出 | Desktop 里怎么做 |
|---|---|---|---|
| **探索** | 弄清现状或可选方向 | 事实、选项 | 提示里写明“不要改文件”；或使用 **Plan** 模式 |
| **计划** | 决定怎么做 | 一份可审阅的方案 | **Plan** 模式；官方说明它探索并提出计划，不修改源代码 |
| **小样** | 用很小的代价验证不确定的做法 | 一个能运行的最小例子 | **Manual**，限定在单独目录 |
| **执行** | 完成明确的任务 | 改动 + 验证证据 | **Manual** 或 **Accept edits**，必要时 **Auto** |

### 权限模式在这里的作用

权限模式（第 2 章介绍）不是“流程阶段”，而是**你把多少自主权交给 Claude**：

- **Plan**：只探索和提议，不改源代码。官方注明它仅作用于当前会话（不会被记成这个文件夹的默认模式）。
- **Manual**：每次改文件或运行命令都问你。
- **Accept edits**：自动接受文件编辑与常见文件系统命令（`mkdir`、`touch`、`mv`），其他终端命令仍询问。
- **Auto**：由后台分类器检查，风险动作被拦截而不是询问你。它对模型有要求（官方列出 Opus 4.6 及以上、Sonnet 4.6 及以上、Haiku 5.5 或 Fable 系列），管理员也可以关闭。

在 Desktop 中，权限模式菜单的快捷键是 `Cmd+Shift+M`（macOS）；官方特别注明 **`Shift+Tab` 在 Desktop 里不会循环切换权限模式**（那是 CLI 的习惯）。如果你在网上看到 CLI 教程让你按 `Shift+Tab`，在 Desktop 里要改为使用这一排控件中的权限模式选择器。

> **Plan 模式不是永久关卡。** 它是一个让你在不确定时暂停下来的选项。需要时进入，计划确认后切换到合适的执行模式，事情简单时完全不进入。

## 3. 一套四个问题的判断法

遇到任务时，依次问：

1. **需求明确吗？** 不明确 → **先探索**（第 5 章）。
2. **关键做法有把握吗？** 没把握 → **先做小样**。
3. **有可靠的验收方式吗？** 没有 → **先把验收写出来**（第 6 章）。
4. **同一问题已连续失败两次以上吗？** 是 → **先调查根因**（第 22 章）。

这四个问题里，**第 4 个优先级最高**。官方最佳实践写得很直接：如果你在同一个问题上纠正了 Claude 两次以上，上下文已被失败的尝试污染，建议清空后用一个整合了所学教训的、更具体的提示重新开始。

如果四个问题的答案都是“没问题”，才**直接执行**。

## 4. 四个情境的练习

用上面的判断法自己先回答，再对照后面的参考。

**情境 A**：你想把 LinkShelf 页面标题的错别字“收蔵”改成“收藏”。
**情境 B**：你想“让收藏页更好用”，但没想好具体改什么。
**情境 C**：你想让收藏自动同步到另一台电脑，但没做过，不知道不用服务器能否做到。
**情境 D**：Claude 已经两次修改“删除按钮”，刷新后条目仍然回来。

### 参考解释

- **A：直接执行。** 一句话就能描述这次 diff，需求明确、验收简单（看页面）。计划只是浪费时间。
- **B：先探索。** 需求模糊，用第 5 章的“三个方向”提示。
- **C：先做小样。** 先验证“纯静态网站能否做同步”这个关键不确定点，别直接做完整功能。你可能会发现需要服务器，那时再决定缩小范围。
- **D：先调查根因。** 这正是第 22 章的主题：停止修补，收集证据。

每个情境都可能有第二种合理答案。**重要的是你的理由**：你依据了哪个问题？

## 5. 动手：在 Desktop 里切换一次模式

1. **[Desktop Code]** 新建一个 Local 会话，目录用 `lab-a`。
2. 把权限模式设为 **Plan**。
3. 发送：

   > 我想给收藏加一个“置顶”功能。请先看现有代码，给我一份实施计划：要改哪些文件、数据格式是否变化、怎样验证。不要修改任何文件。

4. 阅读计划。**你应该核对的不是文笔，而是：** 它有没有提到存储格式变化的影响？验证方式是否都可以在浏览器里观察？
5. 满意后把权限模式切到 **Manual**，发送：

   > 按你刚才的计划实施，并按计划里的验证步骤告诉我怎么检查。

6. 用第 4 章的三种证据核对。

**观察：** 在 Plan 模式时，工作区里有没有文件被改动？切到 Manual 后，第一次改动有没有出现审批？

## 6. 失败分支：计划看起来很好，实施却偏了

计划写得头头是道，不代表执行会遵守。常见偏差：

- 计划说“不改存储格式”，diff 里却新增了字段；
- 计划说改两个文件，实际改了五个。

办法：**把计划当作验收标准**。看 diff 时逐条对照；偏离处用第 4 章的“diff 行评论”指出。若偏差很大，拒绝变更并说：“请严格按计划，计划里没有的不要做。”
