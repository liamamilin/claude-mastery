# 第 04 章｜桌面预览、集成终端与变更面板

> 本章终点：你用 Lab A（LinkShelf）改一个标题，并同时拿到三种互相独立的证据——**浏览器里的页面、终端里的命令输出、变更面板里的 diff**。你能解释为什么三者缺一不可，以及某一种缺失时该怎么办。

## 1. 为什么要三种证据

第 3 章你对照了“对话记录、文件、浏览器”。在 Desktop 里，这些检查不必切到别的程序，工作区本身提供了几个面板：

| 面板 | 回答的问题 | 典型证据 |
|---|---|---|
| **Changes**（diff） | 到底改了哪些行？有没有越界？ | `+3 -3`，逐行对照 |
| **Terminal**（集成终端） | 命令能跑吗？输出是什么？ | 命令的真实输出 |
| **Browser**（预览） | 用户看到的是什么？ | 页面、点击后的反应 |
| **Files** | 文件现在的内容是什么？ | 直接打开、查看或编辑 |

官方参考列出的窗格还包括 **Plan**、**Background tasks**、subagent 窗格，以及 macOS 上的 **iOS Simulator**。你可以把窗格拖到喜欢的位置、拖边缘调整大小；用 `Cmd+\`（macOS）或 `Ctrl+\`（Windows）关闭当前聚焦的窗格。窗格布局需要 Desktop 较新的版本（官方写明 v1.2581.0 或更高）；如果你的界面看起来不同，先回第 2 章核对版本。

> **名称以你的应用为准。** 本章用的面板名、快捷键均来自 2026-10-26 的官方 Desktop 参考；如与你屏幕上的不同，以屏幕为准，并把差异记在笔记里。

## 2. 准备：把 Lab A 当作练习项目

Lab A 是资料包里的小工具 LinkShelf：三个文件（`index.html`、`app.js`、`styles.css`），数据存在浏览器 `localStorage`，不需要账号、不需要安装 npm。

1. **[系统文件管理器]** 把 `cases/lab-a-links/` 整个文件夹复制到一个练习位置，例如 `~/claude-lab/lab-a`。**不要直接在资料包里练习**——你之后可能想保留一份干净的原件。
2. **[Desktop Code]** 新建会话，环境选 **Local**，文件夹选 `lab-a`，权限模式 **Manual**。

## 4. 面板一：Browser——启动开发服务器并预览

LinkShelf 是静态页面，但“通过 `http://` 访问”比“双击文件（`file://`）”更接近真实网站，而且部分浏览器对 `file://` 下的 `localStorage` 有限制。所以我们用一个本地静态服务。

### 4.1 `localhost` 是什么

`localhost` 是“这台电脑自己”的网址。启动一个本地服务后，你的浏览器访问 `http://localhost:端口号/`，请求不会离开你的电脑。它只用于开发和预览；将来放到 GitHub Pages 的网站不需要你的电脑一直开着服务。

### 4.2 配置预览服务器

Desktop 用项目里的 `.claude/launch.json` 记录预览服务器。官方参考列出的主要字段有 `name`、`runtimeExecutable`、`runtimeArgs`、`port`，另有 `cwd`、`env`、`autoPort` 等。对 Lab A，一个可用的配置是：

```json
{
  "version": "0.0.1",
  "configurations": [
    {
      "name": "LinkShelf (static)",
      "runtimeExecutable": "python3",
      "runtimeArgs": ["-m", "http.server", "48123", "--bind", "127.0.0.1"],
      "port": 48123
    }
  ]
}
```

它的意思是：用 `python3` 启动一个标准库自带的静态文件服务，监听 48123 端口。你可以让 Claude 帮你创建这个文件，**发送到 [Desktop Code]**：

> 请为当前项目创建 `.claude/launch.json`，让 Desktop 能用 python3 启动一个静态文件服务预览 `index.html`，端口 48123。创建前先告诉我这个服务只绑定 127.0.0.1。

> **端口冲突是常见的失败。** 如果你的机器上 48123 已被别的程序占用，预览会启动失败并提示端口被占用。解决办法是换一个端口，同时改 `runtimeArgs` 和 `port` 两处。不要停止你不认识的进程。作者在写本书时就遇到过：常用端口（8765、8791）已被其他项目占用，所以选了 48123。

### 4.3 打开 Browser 窗格

点击标题栏里的 **Browser**，或按 `Cmd+Shift+B`（macOS）/ `Ctrl+Shift+B`（Windows）。窗格头部的 **Dev servers** 菜单可以启动或停止在 `launch.json` 里配置的服务器。启动后，页面应出现在窗格里。

Browser 窗格的 **⋮** 菜单里有 **Auto-verify changes** 等选项；官方说明 `autoVerify` 默认是开启的——这意味着 Claude 修改代码后可以自己看一眼运行的页面。第 17 章会专门讨论它能验证到什么程度、不能验证什么。

**注意：** 官方说明 Browser 使用干净的配置文件，不含你保存的登录状态；如果要以自己的身份操作已登录的网站，需要 Claude in Chrome 扩展，那是另一个工具，本章不涉及。

## 5. 做一次“有三种证据”的修改

**发送到 [Desktop Code] 的提示框（允许修改文件）：**

> 请把页面主标题“LinkShelf”改成“我的收藏架”，浏览器标签页里的标题也一并改成“我的收藏架 · LinkShelf”。只改标题文字，不要改任何别的行。

在 Manual 模式下批准变更后，依次收集证据。

### 证据 1：Changes 窗格（diff）

点击会话里出现的 `+N -M` 计数，或点击标题栏的 **Changes**（macOS 快捷键 `Cmd+Shift+D`）。你会看到按文件分组的改动。

**你应该核对：**

- 被改动的文件只有 `index.html`（标题通常写在这里）；
- 变更行数很小，大约两到三行；
- 被改的内容就是标题，没有顺手“优化”别的东西。

在 diff 视图里点击任意一行就能评论，用 `Cmd+Enter`（Windows 为 `Ctrl+Enter`）提交全部评论，Claude 会读取你的评论并修改。这是**最精确的纠偏方式**——你可以指着具体的一行说“这行不要动”。

### 证据 2：Terminal——一条命令

按 `Ctrl+\``（官方给出的终端快捷键）或点击标题栏的 **Terminal**。终端与会话共享工作目录。输入：

```sh
grep -n "我的收藏架" index.html
```

`grep` 是在文件中查找文字的命令；`-n` 表示同时显示行号。输出应列出包含新标题的行。

如果没有安装 `grep`（例如 Windows 的 PowerShell），使用 `Select-String -Path index.html -Pattern "我的收藏架"`。**这一步的意义不是学命令，而是看到：文件里的文字与对话里说的一致。**

### 证据 3：Browser——页面真的变了

在 Browser 窗格刷新页面。标签页标题与主标题都应是新文字。然后做一次**回归检查**——确认这次修改没有破坏原功能：

1. 添加一条收藏（标题随便写，网址用 `https://example.com`）。
2. 刷新页面，它仍在。
3. 删除它，再刷新，它消失。

标题改了，功能还在，才算“可用”。

## 6. 三者为什么缺一不可

- **只有 diff**：知道改了什么，不知道改了以后能不能运行。
- **只有页面**：知道现在看起来对，不知道有没有被悄悄改了别的东西。
- **只有终端输出**：知道文件里有文字，不知道浏览器里怎么显示。

![三种证据互相补位：Changes、Terminal、Browser 各自回答不同问题，三者一致才可信。](/figures/three-evidence.svg)

当你用任何一种证据说服自己“完成了”，就在不知不觉地把另外两种风险放在一边。第 17、18 章会把这种思路扩展成验证体系。

## 7. 失败分支

**A：Browser 窗格是空白，或提示无法连接。**
先看 Dev servers 菜单里服务器状态，再看终端里有没有报错。常见原因：端口被占用；`launch.json` 里 `python3` 路径不对（Windows 上可能是 `python` 或 `py`）；`runtimeArgs` 写成了一个字符串而不是数组。

**B：页面显示的是改之前的内容。**
可能是浏览器缓存，也可能 Claude 改的不是你正在预览的目录。让它报告被修改文件的完整路径，与服务的根目录对照。

**C：diff 里出现了不认识的文件，比如 `.DS_Store`。**
这是系统自动生成的杂项文件，与任务无关。后面讲 Git 时会学到用忽略规则处理；现在只需要知道“看见了不属于任务的改动”本身就是一个信号，应该问 Claude 这是什么。

## 8. 独立练习

1. 让 Claude 把“删除”按钮的文字改成“移除”。这次**先自己想好**：需要收集哪三种证据？你期望 diff 大概有几处改动（提示：按钮文字在 `app.js` 里，辅助文字 `aria-label` 也可能带有“删除”二字）？
2. 做完后，对照你的预期与实际。如果有差异，是 Claude 越界了，还是你的预期漏了？

## 9. 掌握检查

1. diff 窗格能证明什么，不能证明什么？
2. `localhost` 的网址为什么只能在你自己的电脑上打开？
3. 你的页面显示是旧的，但 diff 显示已改。你先查什么？
