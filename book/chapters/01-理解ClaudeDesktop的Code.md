# 第 01 章｜Claude Desktop 的 Code，究竟在做什么？

> 本章终点：你可以打开正确的 **Code** 工作区，指出 Claude 的一句回答、一次真实文件操作、以及能够验证结果的证据分别是什么。**本章不要求先掌握编程。**

## 1. 一个容易发生的误会

假设你在普通对话里说：“请帮我做一个网页”。Claude 可以提供建议或一段 HTML 代码，但这时它未必已经把文件放进你希望的项目文件夹。代码写在回答里，和网页已经能在你的电脑打开，是两个不同的事实。

Claude Code 则是开发代理工具。它可以在指定的工作环境中查看文件、修改文件、执行命令。通过 Claude Desktop 的 **Code** 标签页，你可以把这种工作过程放在一个看得见的项目空间里，而不只是读最后一句“完成”。

这本书把“完成”拆成三个层次：

1. **说明**：Claude 表达了它将做什么、认为自己做了什么。
2. **操作**：它实际访问、生成或修改了哪些项目文件，运行了什么命令。
3. **结果**：这些改动能不能被打开、使用或验证；它们是否实现你原本的目标。

第三层最重要。漂亮的总结不能替代可打开的页面。

## 2. 分清 Desktop 里三个入口

Claude Desktop 的界面可能会出现 Chat、Cowork、Code，具体布局随版本演进。它们目的不同：

| 入口 | 你在做的事 | 在本书中如何使用 |
|---|---|---|
| **Chat** | 对话、提问和探索 | 可以帮助你想清楚目标，但不是默认的项目开发界面 |
| **Cowork** | 更一般的文件与代理工作 | 了解它和 Code 的区别；不把它的菜单写成 Code 操作 |
| **Code** | 让 Claude 在项目上实施开发工作 | **全书默认路径** |

> 操作名称以你当前安装的版本为准。查阅 [Anthropic 的 Code Desktop 参考](https://code.claude.com/docs/en/desktop) 和 [桌面入门](https://code.claude.com/docs/en/desktop-quickstart)，避免依赖过期截图。

## 3. 第一次打开一个真正的项目

这里先做一个没有破坏性的观察任务。

### 步骤 A：准备文件夹

**[系统文件管理器]** 在你容易找到的位置新建一个文件夹，例如 `my-claude-lab`。它只是学习用的练习目录，不含私人文档。这个文件夹就是本次任务的**项目工作目录**：Claude 是否能访问它，取决于你创建会话时选择的环境和文件夹。

### 步骤 B：新建 Code 会话

**[Desktop Code]** 打开 Claude Desktop，找到 **Code** 标签页，创建一个新会话。选择 **Local**（本地）环境，并选择刚才的 `my-claude-lab` 文件夹作为项目目录。权限模式尽量选择你能逐项查看变更的方式；不同账号和版本可能显示不同模式，按当前界面核对。

不要先选择 Cloud/SSH，也不要在这一章连接第三方工具。我们的目标只是观察本地文件变化。

### 步骤 C：先观察，不让 Claude 修改文件

**发送到 [Desktop Code] 的提示框：**

> 请先确认你能看到当前项目目录，并说明目录中有哪些文件。暂时不要新增、删除或修改任何文件。请把你实际观察到的内容与推测分开说明。

如果目录是空的，正常结果是 Claude 指出没有现有项目文件。若它把其他仓库的文件当作当前文件，先检查会话选错的目录，不要继续在错误目录上操作。

**现在你已经学会第一项判断：**Claude 的解释只是观察结果的表达，真正的依据仍是当前目录与实际文件。

## 4. 从一句任务到一个可打开的文件

继续在刚才的会话中发送：

> 请在当前练习目录创建 `hello.html`。做一个中文页面，标题是“我的第一个 Claude Code 页面”，正文写“这页来自真实项目文件”。只需要 HTML 和少量内置 CSS，暂时不要安装依赖。完成后告诉我创建了什么文件，以及我如何亲自打开它。

### 你应该看到什么？

**[Desktop Code]** 可能显示创建文件的操作记录，Changes/diff 面板里可能出现新增内容；**[系统文件管理器]** 打开文件夹，应该出现 `hello.html`。

双击该文件或用普通浏览器打开。你需要看到标题和正文。不需要和 Claude 生成的每个 HTML 属性完全一致；**能看到要求的内容，并且确实来自文件**才是本章的验收。

如果没有文件，先确认会话中的项目文件夹是不是正确。如果有文件但浏览器打开空白，请检查扩展名是不是 `.html`、文件内容是否为空，或者请求 Claude 查看实际文件，而不是立刻要求它“重做整个网站”。

## 5. 认识三个工作证据

你可以试着在 Code 标签页找到相应面板（名称和位置可能随版本变化）：

- **文件内容**：文件面板或系统文件管理器告诉你产物具体是什么。
- **Diff / Changes**：变更对照告诉你这次哪些内容是新加或修改的。
- **浏览器预览**：打开页面后，你可以观察真实显示效果。后续章节会介绍 Desktop 的 Browser pane、开发服务器和自动验证。

当这三种证据一致时，“完成”的可信度会比单看会话总结高得多。

## 6. 为什么本章还没有安装复杂工具？

你以后会遇到 Node、Git、工作树、Skills、MCP 和 Hooks，但它们不是让第一个 HTML 文件存在的必要条件。大部分学习困难来自前置知识被一下塞太多。你先掌握最小闭环，再在需要时添加工具。

## 7. 常见问题

**Q：我在 Code 页没看到本地目录选项。**

A：确认你使用的是 Claude Desktop 中的 Code 标签页，而不是 Chat 或其他入口；检查是否登录具有 Claude Code 权限的账号、应用版本、以及当前平台。不同组织可能限制环境类型。若仍无法创建本地会话，记录看到的选项并对照官方 Desktop 入门指南。不要凭空假设某个按钮总在那里。

**Q：Claude 说“创建成功”，但找不到文件。**

A：先让它报告实际写入路径，再核对你的练习目录和当前会话是否一致。不要继续添加新功能。

**Q：为什么还要自己打开页面？**

A：代理给出的是工作过程和解释，而用户真正需要的是可用结果。自己打开，是最低成本的独立检查。

## 8. 独立练习

不看上面的提示词，自己让 Claude 将页面改成一个两栏的小卡片：左边写“输入”，右边写“结果”。要求它只改 `hello.html`。然后回答：

1. 你通过哪个文件确认它真的修改了项目？
2. 你通过哪个动作确认浏览器显示了改动？
3. 如果它创建了 `hello2.html` 而不是改原文件，你该提供什么信息让它回到目标？

你能说出文件、路径、变更和浏览器行为，就已经掌握这章的核心。
