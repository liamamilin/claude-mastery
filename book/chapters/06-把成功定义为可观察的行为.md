# 第 06 章｜把成功定义为可观察的行为

> 本章终点：你为 LinkShelf 写出一页**完成条件清单**，每一条都是“做某个动作 → 看到某个结果”的形式，并且包含失败时应出现的反馈。你会用它在下一章里评价 Claude 的成果。

## 1. “做得好看一点”无法验收

假设你对 Claude 说：“把收藏页做得更好用、更好看。”它会交付一个版本。你怎么判断对不对？只能凭感觉。凭感觉评价有两个后果：

1. 无法和 Claude 达成一致——你说“还不够好”，它不知道差在哪里。
2. 无法发现悄悄坏掉的东西——新页面更好看了，但刷新后数据不见了，你可能没注意。

解决办法是把目标翻译成**可观察的行为**：用一个具体动作触发，能被你亲眼确认。

## 2. 一条合格的完成条件长什么样

一条好的条件有四个部分：

> **在什么状态下** → **做什么动作** → **应该看到什么** → **看不到时意味着什么**

例如：

> 页面里没有任何收藏时，添加“标题：官方文档，网址：https://code.claude.com/docs”，列表出现一条“官方文档”；刷新页面后它仍然存在。

对比一下几个不合格的写法：

| 不可观察 | 可观察 |
|---|---|
| “保存功能正常” | 添加一条 → 刷新 → 仍在列表中 |
| “有错误处理” | 标题留空点保存 → 页面显示“请填写收藏标题。”，列表不变 |
| “体验流畅” | 添加后输入框被清空，光标仍在页面上，无需手动刷新 |
| “代码质量好” | 暂不在本章验收；见第 18、19 章 |

最后一行很重要：**有些目标现在无法被观察**，那就老实地推后，不要硬写一个看似可检查的句子。

## 3. 动手：写 LinkShelf 的完成条件

Lab A 的原始行为已经在作者的浏览器验收中通过（见 `STATUS.md`）。我们现在假设要加“按标题搜索”，把完成条件写成清单。

### 步骤 1：列出“已有的、不能被破坏的”

这是最容易被忘记的一类条件，称为**回归条件**：

- [ ] 添加一条有效收藏：列表增加，提示“收藏已保存。”
- [ ] 刷新页面：收藏仍在
- [ ] 删除：列表减少，刷新后仍然不在
- [ ] 标题为空：显示“请填写收藏标题。”，不新增
- [ ] 网址不是 http/https：显示“请输入包含 http:// 或 https:// 的有效网址。”，不新增

### 步骤 2：列出“新功能要做到的”

- [ ] 有 3 条收藏：“官方文档”“博客”“官方示例”。搜索框输入“官方”：只显示包含“官方”的两条
- [ ] 清空搜索框：三条全部恢复
- [ ] 搜索结果为空：显示一句说明（例如“没有匹配的收藏”），而不是空白
- [ ] 搜索时刷新页面：数据不丢失（**搜索只是显示过滤，不能删数据**）

### 步骤 3：列出边界

- [ ] 搜索框输入大写字母、空格：行为符合你的预期（先决定“是否区分大小写”）
- [ ] 一条收藏都没有时，搜索框不报错

### 步骤 4：标出“暂不验收”

- 手机屏幕上的布局
- 超过 1000 条数据时的速度

写下来即可，下一轮再做。**明确“不做什么”，和“要做什么”一样重要。**

## 4. 把清单交给 Claude

**发送到 [Desktop Code] 的提示框：**

> 请给 `lab-a` 增加“按标题搜索”。完成条件如下，请逐条对照；完成后告诉我哪几条你自己验证过、怎么验证的，哪几条需要我在浏览器里验证：
>
> （把上面的清单粘贴在这里）

这样做的收益：

- Claude 有了判断“何时算完”的依据；
- 你有了审查的清单，不需要重新想“我该点什么”；
- “你自己验证过”和“需要我验证”被分开，防止它把没验证的东西说成已验证。

## 5. 失败分支：清单写得太满

初学者常犯的错误是写 30 条条件，结果没人逐条验证。办法：

- 每条只写**一个动作**；
- 分成“必须”“最好”“暂不”三档；
- 第一次只验收“必须”。

## 6. 独立练习

为“导出 JSON”功能（点击按钮，下载收藏列表）写 6 条完成条件，至少要有：

- 一条回归条件；
- 一条失败路径（例如没有任何收藏时点击导出，应该发生什么）；
- 一条你决定“暂不验收”的内容。

写完后问自己：每一条，我都能在浏览器里亲眼看到吗？

## 7. 掌握检查

1. “保存功能正常”为什么不合格？怎样改写？
2. 什么是回归条件？为什么它容易被遗忘？
3. 为什么要让 Claude 区分“自己验证过”和“需要我验证”？
