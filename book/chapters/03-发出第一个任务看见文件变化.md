# 第 03 章｜发出第一个任务，看见文件变化

> 本章终点：你让 Claude **先读、再做**，在 Manual 模式下批准一次真实修改，然后在系统文件夹里找到成果并用浏览器打开。你能分辨“任务描述”“操作记录”“文件内容”三样东西。

## 1. 从第 1 章的两个任务说起

第 1 章里你让 Claude 创建过 `hello.html`。那次的重点是区分“说明、操作、结果”。这一章把动作做得更像真实工作：

- 不再让 Claude 直接动手，而是**先读后做**；
- 任务不是一个静态页面，而是一个小的、有结构的页面，需要你来判断是否做对；
- 你会第一次使用 `@文件名` 把具体文件交给 Claude。

## 2. 准备

- 使用第 2 章建好的 **Local** 会话，权限模式为 **Manual**。
- 练习目录里可以已有 `hello.html`；没有也没关系。
- 打开 **[系统文件管理器]** 窗口，放在能同时看到的位置。你要同时观察两边。

## 3. 第一步：先读，不改

**发送到 [Desktop Code] 的提示框（只读）：**

> 请先看一下当前项目目录里有什么，用两三句话概括。暂时不要新增、删除或修改任何文件。

先读的理由很朴素：如果 Claude 对目录的描述和你看到的不一致，你在它写入任何文件**之前**就发现了问题。这是成本最低的纠偏点。

## 4. 第二步：给出目标，而不是步骤

**发送到 [Desktop Code] 的提示框（允许创建文件）：**

> 请在当前目录创建 `shelf.html`：一个中文的“我的收藏架”页面。页面上有标题、一个输入框和“添加”按钮，下面是一个空列表，显示“还没有收藏”。现在只需要静态外观，不用实现添加功能，不要安装任何依赖。完成后告诉我创建了哪些文件。

注意这段话的写法：

- 说了**要什么**（页面包含哪些东西）、**不要什么**（暂不实现功能、不安装依赖）；
- 没有指定 HTML 的写法、CSS 的类名，这些细节让 Claude 决定；
- 要求它汇报创建了哪些文件，方便你对照。

### 在 Manual 模式下你会看到什么

Manual 模式下 Claude 会在创建文件前提出变更，并等待你批准。按官方说明，你可以看到一个展示具体改动的 diff，以及接受或拒绝的按钮。

- 先**读 diff**：新建文件的 diff 里，每一行都是“新增”。读一读标题、输入框、按钮的文字是不是你想要的。
- 满意就批准；不满意就拒绝，并告诉 Claude 哪里要改。

批准后，会话里会出现类似 `+N -M` 的变更计数（官方文档里的示例是 `+12 -1`）。点击它可以打开 **diff view**，逐文件查看。

## 5. 第三步：三处对照

现在对照三样东西，它们应该互相印证：

| 看什么 | 在哪里 | 回答的问题 |
|---|---|---|
| 会话里的操作记录 | **[Desktop Code]** 对话区 | Claude 说它做了什么？ |
| 文件本身 | **[系统文件管理器]** 中的 `shelf.html` | 磁盘上真的有这个文件吗？ |
| 页面表现 | **[浏览器]** 双击打开 | 打开后真的是你要的样子吗？ |

只要三者一致，你就完成了一次可信的交付。**只有第一项的“完成”不算数。**

## 6. 第四步：用 @ 精准地引用文件

假设你想让标题改成“链接收藏架”。与其说“把那个页面的标题改一下”，不如把文件指给 Claude：

**发送到 [Desktop Code] 的提示框：**

> 请把 @shelf.html 的页面标题和主标题都改成“链接收藏架”，其他内容保持不变。

输入 `@` 后跟文件名，输入框会提示可选文件（本地会话中可用；官方注明云端会话要在发送第一条消息之后才会列出）。`@` 的价值在于：**它消除了“哪个文件”的歧义。** 当目录里有 `hello.html` 与 `shelf.html` 时，这一点尤其重要。

改完后再做一次三处对照，并特别看 diff：被改动的只应是标题相关的两行。如果出现了无关改动，说明任务范围没有说清，这正是下一节的材料。

## 7. 失败分支：它改多了

假设你只要求改标题，diff 里却出现了整个页面被重写的情况。

不要接受，也不要急着重来。**拒绝这次变更**，然后发送：

> 刚才的改动超出了我的要求。我只希望修改标题文字，其余部分原样保留。请重新提议一次，只改标题。

这里有两个习惯值得建立：

1. 在 Manual 模式里，拒绝是廉价的。没有任何文件被改动，也不需要“撤销”。
2. 纠偏时说清**哪里越界**与**期望的范围**，而不是只说“不对”。

## 8. 小技巧：中途改主意

如果 Claude 正在工作时你发现任务写错了，不必等它结束：点停止按钮可以立刻中断；也可以直接输入更正并按 **Enter**——官方说明这样不会打断当前动作，Claude 会在当前动作完成后读取你的更正。`Esc` 也可以停止回应。第 14 章会系统讲打断与纠偏。

## 9. 独立练习

不看本章的提示词，自己完成以下任务：

> 让 Claude 把 `shelf.html` 的背景改成浅米色，并让输入框占满整行宽度。

然后回答：

1. 你通过哪个文件确认真的改了？
2. diff 里有没有不该出现的改动？
3. 如果它同时改了 `hello.html`，你发什么话把它拉回来？

## 10. 掌握检查

1. “会话里说完成了”与“磁盘上有文件”有什么区别？
2. 为什么先让 Claude 读取目录，再让它创建文件？
3. `@文件名` 解决的是什么问题？
