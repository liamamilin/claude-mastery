# 第 29 章｜复杂目标拆解成连续的可用交付

> 本章终点：面对一个“一口吃不下”的目标，你能把它拆成**每一步都可用、可验证、可回退**的切片序列，并为每一片写出完成条件；你会用本书项目自己的真实推进过程，检验“纵向切片”与“横向铺开”的区别。

## 1. 大目标的两种推进方式

目标：“做一个包含收藏、搜索、标签、导出、同步的链接管理工具。”

**横向铺开**：先把所有页面的外观做完，再做所有数据结构，再接上所有功能。最后一天才第一次把整个东西跑起来——这时才发现各部分彼此对不上。

**纵向切片**：先做一条**从头到尾都能用的最窄路径**：添加一条收藏 → 刷新还在 → 能删除。它很简陋，但每个环节都是真的。然后一片一片加宽。

纵向切片的好处，正是前面各章反复出现的：**每一步都能被验证；失败的范围小；随时可以停在“已经能用”的状态。**

## 2. 拆解的四个动作

1. **写出最终的可观察结果**（第 6 章）：“用户能……”，一句话。
2. **画出最窄的完整路径**：只留下让这句话成立的最少环节。
3. **按风险排序加宽**：不确定性最高的环节尽早做小样（第 8 章）。
4. **每一片写完成条件**：动作 → 结果；包含回归条件。

### 一个对照表

| | 横向铺开 | 纵向切片 |
|---|---|---|
| 第一次能完整运行 | 接近结束时 | 第一天 |
| 出错时的排查范围 | 整个系统 | 刚加的那一片 |
| 中途被打断 | 手里是半成品 | 手里是一个可用的小版本 |
| 对 Claude 的指令 | 大而模糊 | 小而明确 |

## 3. 真实例子：本书项目自己的推进

这个例子不是编的，是本书项目在写作中的真实过程（见仓库提交记录与 `STATUS.md`）：

1. **第一片**：导读 + 第 1–3 章 + 案例 A 浏览器验收 + 网站构建 + 子路径预览。这一片是**整条链路最窄的完整路径**：写作 → 构建 → 预览 → 验证。完成时就能说“这个站点能读”。
2. **第二片**：第 4–8 章 + 一个互动练习。每一章加完都构建并检查；
3. **第三、四、五、六、七片**：每次 4 章，配一个真实案例（Lab B、Lab C、Lab D 回归、Lab E）。**每一片都有实测的事实可写**：在 Lab B 实测中发现了“错误提示被覆盖”的真实缺陷；在 Lab C 实测中确认了窄屏溢出；在 Lab E 的测试里发现了 Node 22 错误信息没有位置信息、Hook 缺 `jq` 时会静默放行。

注意这些发现**都是在小片上跑出来的**。如果等到全部写完再统一验证，这些问题会混在一起，更难定位。

> **反例也值得记录**：本书的章节里很多“Claude Desktop 内的操作”尚未在应用内实测（STATUS.md 与各章事实注记都写了）。这是一个已知缺口，不是已完成。**切片能保证“已验证的部分是真的”，不能保证“没验证的部分是对的”**。

## 4. 动手：为 LinkShelf 设计五片

目标：“一个能搜索、打标签、导出的收藏工具。”现状：Lab A 已能新增、刷新保留、删除。

在一张纸上（或让 Claude 在 Plan 模式下协助），填：

| 片 | 用户能做到什么 | 完成条件（动作 → 结果） | 回归条件 | 风险 |
|---|---|---|---|---|
| 1 | 按标题搜索 | | | 低 |
| 2 | 给收藏加一个标签 | | 旧数据能读出 | **改变数据格式**，高 |
| 3 | 按标签筛选 | | | 依赖片 2 |
| 4 | 导出 JSON | | | 低 |
| 5 | 导入 JSON 恢复 | | 非法文件有提示 | 中 |

**排序理由：** 片 2 改变存储格式，风险最高，应当**尽早做小样**，并紧接着做回归；片 3 依赖它；片 4、5 相对独立。你也可以把片 1 放在最前面——它风险低、见效快、能快速建立信心。**这是一个有取舍的决定，不是唯一答案。**

### 对 Claude 的指令

每一片一个会话，配 `HANDOFF.md`（第 12 章）：

> 当前是第 N 片：（目标）。已完成的片见 @HANDOFF.md。完成条件如下：（粘贴）。只做这一片，不要提前做后面的。完成后更新 HANDOFF.md：已验证什么、没验证什么。

## 5. 每一片结束的三个动作

1. **验证**：按完成条件和回归条件；
2. **提交**：一个你愿意回到的状态（第 15 章）；
3. **写交接**：更新状态文件。

三个动作做完，这一片才算“完成”。**如果其中一个做不了（比如没法验证），这一片不能算完成**，要回到第 24 章的决定。

## 6. 失败分支：切片太大，或者不独立

信号：

- 一片做了一整天；
- 做完这一片，页面处于“不能用”的状态；
- 这一片的验证要等下一片才能做。

处理：**把这一片再拆**，直到每一片结束时系统都可用。

另一个信号：你发现后面的片需要推翻前面的片。这说明最初的“最窄路径”选错了，或者**数据结构应当先做小样**（回到第 8 章）。这没有错，是一个需要及时做出的决定。

## 7. 独立练习

挑一个你自己真正想做、但感觉很大的目标。写出：①最终可观察的一句话；②最窄的完整路径；③前三片（含完成条件）。给一位朋友看，问他：**第一片做完后，我能不能亲眼看到一个能用的东西？**

## 8. 掌握检查

1. 纵向切片和横向铺开最大的区别是什么？
2. 为什么风险最高的环节要尽早做小样？
3. 一片“完成”需要哪三个动作？
