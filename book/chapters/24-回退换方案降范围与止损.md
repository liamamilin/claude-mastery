# 第 24 章｜回退、换方案、降范围与止损

> 本章终点：面对一个已经投入很多的失败任务，你能在**修下去、回退、换方案、缩小范围、暂停**五种选择中做出有证据的决定，并写下一页简短的决定记录。你不会再因为“已经做了这么多”而继续硬撑。

## 1. 沉没成本的陷阱

三个小时过去，Claude 已经改了十几处，页面仍然不对。你很想说“再试一次”。

这种冲动有名字：**沉没成本**。已经花掉的时间无法收回；决定下一步时，唯一该问的是：**从现在起，哪条路到达目标的期望代价最低？**

官方最佳实践里有一条可直接引用的经验：如果你对同一个问题纠正了两次以上，上下文已被失败的尝试污染，与其继续纠正，不如 `/clear` 后用一个吸收了教训的更具体的提示重新开始；官方的说法是，一个干净的会话加更好的提示，几乎总是胜过累积了许多纠正的长会话。

## 2. 五个选项

| 选项 | 含义 | 适用信号 |
|---|---|---|
| **继续修** | 当前路线合理，只差一个明确的修复 | 已找到根因、有最小修复、验证条件清楚 |
| **回退** | 回到已知良好的版本 | 改动越来越大、你已无法确定哪些改动是必要的 |
| **换方案** | 目标不变，路线改变 | 当前方案的某个关键假设被证伪 |
| **降范围** | 目标缩小，先交付一部分 | 剩余部分风险高，已完成部分有价值 |
| **暂停** | 停下收集材料 | 缺关键信息，继续只会猜 |

> 它们不是互斥的：常见的是“回退 + 降范围”。

## 3. 判断问题

按顺序问自己：

1. **我现在能说出根因吗？**（能 → 继续修；不能 → 第 5 个问题）
2. **最近的几次尝试，让我离根因更近了吗？**（没有 → 说明在乱撞）
3. **有没有已知良好的版本？**（有 → 回退成本低；没有 → 先别动，保护现状）
4. **剩余目标里，哪一部分最有价值？**（用于降范围）
5. **缺什么信息？**（用于暂停与收集证据，回到第 21、22 章）

## 4. 动手：Lab D 里的一次“失败的修补”与决定

Lab D 的故障（删除后刷新又出现）已被诊断（第 22 章）。我们现在**模拟一条糟糕的路径**，练习做决定。

### 准备

把 `cases/lab-d-persistence` 复制为 `lab-d`，在其中建立 Git 基线（第 15 章的命令）：

```sh
git init -b main
git add -A
git commit -m "基线：故障版"
```

### 三次“补丁”

**[Desktop Code]**（Manual），故意模仿第 22 章里的坏习惯，逐轮发送：

1. “删除按钮点了没用，请加大按钮点击区域。”
2. “还是不行，请给按钮加一个防抖。”
3. “请把整个列表渲染改成用一个新的状态库。”

**每轮之后，做三件事：**

- 看 `git diff --stat`，记录改了多少；
- 在浏览器里复现“删除 → 刷新”，记录是否仍然复现（**作者实测：起始版本的复现步骤稳定，见第 22 章**）；
- 问：我离根因更近了吗？

### 做决定

三轮之后问自己第 3 节的问题。答案几乎一定是：**不能说出根因；没有更近；有已知良好版本（基线）。**

因此选择 **回退**：

```sh
git status --short
git restore .
git status --short
```

`git restore .` 会丢弃**所有**未提交的改动（第 15 章的警告同样适用）。因为基线已提交，这是安全的。第二次 `git status --short` 应无输出。

### 换路线：用证据

回到第 22 章的做法：在新会话（Plan 模式）里让 Claude 先给“已知 / 假设 / 最小判别实验”，做那个 `localStorage` 前后对照，再做**一行**的最小修复。

对比两条路线：

| | 三次补丁 | 证据路线 |
|---|---|---|
| 改动大小 | | |
| 到达可用的轮数 | | |
| 我能解释为什么有效吗 | | |

## 5. 降范围：什么时候该只交付一部分

假设你要给 LinkShelf 同时加“搜索 + 标签 + 导出”，搜索已做好并验证，标签搞了三轮还不稳定。

**降范围的做法：**

1. 先把搜索**提交**（保护已验证的成果）；
2. 把标签的未完成改动放到另一个分支或直接丢弃；
3. 在 `HANDOFF.md`（第 12 章）里写：“标签：失败原因、已知信息、下次从哪里开始”；
4. 交付搜索。

这样你得到的是一个**可用的、较小的**结果，而不是一个“看起来更完整、实际上不可用”的结果。

## 6. 一页决定记录

决定做完后，写一份**一页以内**的记录（可以让 Claude 起草，你来审）：

```markdown
# 决定记录：（任务名）
- 日期：
- 现象：（动作 → 结果 → 期望）
- 已尝试：（每次做了什么，结果）
- 证据：（排除了什么，仍不确定什么）
- 决定：回退 / 换方案 / 降范围 / 暂停 / 继续修
- 理由：（一两句，引用上面的证据）
- 下一步：（具体到文件或检查）
- 没有验证的：
```

**不要把它变成冗长的复盘。** 一页就够。它的价值在于：下一次你（或另一个会话）打开它，能立刻知道别重复什么。

## 7. 失败分支：回退之后仍想“再试一次”

回退并不意味着必须停止；它意味着**在更好的起点上重新开始**。允许“再试”，但要求：

- 先写出这次**和上次有什么不同**（新的证据或新的假设）；
- 给自己一个上限，例如“再试一次，不行就降范围”。

没有新证据的“再试一次”，不是尝试，是赌博。
