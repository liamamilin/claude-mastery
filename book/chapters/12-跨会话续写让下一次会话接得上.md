# 第 12 章｜跨会话续写：让下一次会话接得上

> 本章终点：你为一项做到一半的任务写出一份 `HANDOFF.md`，关掉会话，在**全新会话**里只靠它让 Claude 接着做，并验证“接上了”——它说得出做到哪里、下一步是什么、哪些事没有验证。

## 1. 长对话不是长期记忆

很多人把一个会话当成“项目的记忆”：一直聊下去，什么都在里面。问题有三个：

1. **上下文是有限的。** 官方最佳实践开篇就说，大部分建议都围绕一个约束：上下文窗口会很快填满，且填得越满性能越差。
2. **杂乱的历史会拖累判断。** 官方列出的失败模式之一是“厨房水槽会话”：同一会话里混着不相关的任务。
3. **会话会结束。** 你关掉应用、换了电脑、或者隔了一周。

官方给的做法是：任务之间用 `/clear` 重置；上下文快满时系统会自动压缩（也可手动 `/compact`）；还可以把**一份写好的计划或规格**交给新会话——新会话上下文干净，只专注于实施，而你手上有一份书面依据。

本章把这个思路做成一个朴素的工具：**一份由你和 Claude 一起写、放进项目文件夹的交接文件。**

## 2. 交接文件里应当有什么

| 段落 | 内容 | 为什么 |
|---|---|---|
| 目标 | 这项任务要达成什么（引用第 06 章的完成条件） | 防止新会话重新猜测 |
| 已完成 | 已改的文件，每项附**验证方式与结果** | 区分“做了”和“验证了” |
| 未完成 / 下一步 | 具体到文件和动作 | 新会话可以直接开工 |
| 已知问题与未验证 | 明确写“没验证过” | 防止乐观地假设 |
| 决策与原因 | 选了什么、放弃了什么、为什么 | 防止重复讨论 |
| 运行方式 | 命令、端口（来自第 9 章的 `RUNNING.md`） | 少走弯路 |

**关键纪律：只写已核对的事实，推测要标注。** 一份充满自信却错误的交接文件，比没有交接更糟。

## 3. 动手：做一半，写交接，换会话

### 步骤 1：做到一半

在 `lab-b`（已有第 11 章的 `CLAUDE.md`）中新建会话（Manual 模式），发送：

> 请给任务增加“优先级过滤”。要求：页面上有一个下拉框，选项“全部/高/普通/低”；选“高”只显示 id 1 和 5；没有 `priority` 字段的任务按“普通”处理；不要修改 `data/issues.json`。
>
> **先只做逻辑部分**：在 `src/board.js` 中新增一个纯函数 `filterByPriority(issues, level)`，并在 `test.mjs` 里补充测试，运行 `node test.mjs` 并告诉我结果。**暂时不要改页面。**

这样我们人为制造一个“做到一半”的状态：逻辑和测试完成，界面未做。

用第 4 章的三种证据核对：diff（只应涉及 `board.js` 与 `test.mjs`）、终端（测试输出）。浏览器页面此时不应有变化。

### 步骤 2：写交接

同一会话里发送：

> 现在请在当前目录创建 `HANDOFF.md`，用于让一个完全不了解此前对话的新会话接手。包含：目标；已完成（每项写验证方式和结果）；下一步（具体到文件）；未验证的内容；做过的关键决定及原因；运行方式。只写你实际做过、实际验证过的事，推测请标注“推测”。

### 步骤 3：审阅交接——这一步最重要

打开 `HANDOFF.md`，按下面的检查单审阅：

- [ ] “已完成”里每一项都有验证方式吗？比如“`node test.mjs` 输出 PASS”。
- [ ] 它有没有声称“页面已经可以过滤”？（**不应有**——我们没做页面。）
- [ ] “未验证”里有没有写“浏览器中的真实效果”？
- [ ] 提到的文件都存在吗？（在 Files 窗格逐个点开。）

发现不实之处，直接让 Claude 改，或自己改。**交接文件是你的责任，不是 Claude 的。**

### 步骤 4：换新会话

1. 关闭（或保留不管）旧会话。
2. 新建会话，同一目录。
3. 发送：

   > 请先阅读 @HANDOFF.md，然后只用你自己的话告诉我：这项任务做到哪里了、下一步是什么、有哪些内容还没有被验证。**先不要修改任何文件。**

### 步骤 5：判断“接上了”

对照你自己的记忆，检查新会话的回答：

| 检查 | 通过标准 |
|---|---|
| 进度 | 说出“逻辑与测试已完成，页面未做” |
| 下一步 | 指向 `index.html` / `main.js` 的具体改动 |
| 未验证 | 提到浏览器端尚未验证 |
| 不凭空添加 | 没有声称做过交接文件里没有的事 |

通过后再说“请继续完成页面部分”。完成后，更新 `HANDOFF.md`——**让交接文件始终是当前状态的真实记录**。

## 4. 与 CLAUDE.md、自动记忆有什么不同

| | 内容 | 寿命 |
|---|---|---|
| **CLAUDE.md** | 长期有效的规则与事实 | 长期，偶尔修订 |
| **HANDOFF.md** | 当前这项任务的进度 | 任务结束后可归档或删除 |
| **自动记忆** | Claude 个人笔记 | 本机，不保证精确 |

不要把进度写进 CLAUDE.md——它每个会话都被载入，一旦过期就持续误导。

## 5. Desktop 里的相关控制

官方 Desktop 参考中与续写有关的元素：

- 侧边栏列出所有会话，可以**归档**（在 **View all > Archived** 下找回）；
- 上下文使用情况可在会话详情的 **Context** 卡片和 `/context` 中查看，`/compact` 释放空间；
- 桌面版与独立 CLI 的会话列表并不自动互通（资料包核对卡的说法，官方 Desktop 参考有“Coming from the CLI”一节，作者未逐句核对），**不要假设能互相续写**。

具体按钮位置以你版本的界面为准。

## 6. 失败分支：新会话“接上”了错误的东西

- **症状**：新会话说“页面过滤已完成”，但你没做。
- **排查**：交接文件里是不是写了这句？是 → 交接不实，改文件；否 → 它在编造，要求它指出依据的行。
- **预防**：交接文件里把“已验证”和“未验证”**分成两个标题**，不要混写。

## 7. 独立练习

任选一个你真的打算做的小改动（比如给 LinkShelf 加“导出 JSON”），**故意**在做到一半时停下。只用 `HANDOFF.md` 换会话继续。记录：新会话的第一个回答中，有几处与你的记忆不一致？每一处是交接写得不清，还是模型理解偏差？
