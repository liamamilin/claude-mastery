# 第 30 章｜本地、云端、SSH 与跨端继续

> 本章终点：你能说出 **Local、Cloud、SSH、WSL** 四种环境的文件各在哪里、能力有什么不同；你能判断一个任务该用哪一种；你知道“把一个会话从一端挪到另一端”有哪些前提——**以及哪些事 Desktop 或 CLI 并不替你做。**

> **本章是条件性章节。** 云端与 SSH 取决于你的计划、组织策略与设备。**没有这些条件，你可以安全跳过本章，不影响阅读后面的章节。** 作者没有在云端或 SSH 环境实测，本章全部依据官方文档，且不作未读到内容的断言。

## 1. 先问：文件在哪里

第 2 章你在输入框下选了环境。四种环境的本质区别，不是“快慢”，而是**Claude 操作的文件和命令在哪台机器上**：

| 环境 | 在哪里运行 | 你的文件 | 关闭应用后 |
|---|---|---|---|
| **Local** | 你的电脑 | 直接访问你本机的文件夹 | 会话随应用 |
| **Cloud** | Anthropic 管理的基础设施（组织也可路由到自托管环境） | **不是你的本地副本**；克隆你的 GitHub 仓库 | **继续运行** |
| **SSH** | 你添加的远程机器 | 远程机器上的文件 | 任务可在 Desktop 断开期间继续（有条件，见下） |
| **WSL**（仅 Windows） | 你本机的 WSL 2 发行版 | Linux 侧的原生路径 | 同 Local |

> 来源：官方 [桌面入门](https://code.claude.com/docs/en/desktop-quickstart)、[Desktop 参考](https://code.claude.com/docs/en/desktop) 与 [云端文档](https://code.claude.com/docs/en/claude-code-on-the-web)，2026-10-26。

## 2. 云端会话

官方云端文档（2026-10-26）的要点：

- **可用计划**：Pro、Max、Team，以及 Enterprise 中带有相应席位的用户；若组织有自定义角色，还需要有云端会话权限；
- **它是什么**：在云端基础设施上运行的会话，**关闭电脑后仍继续**；用量与其他 Claude/Claude Code 使用**共享同一份计划额度**，没有单独的云 VM 费用；
- **代码从哪来**：需要连接 GitHub，**VM 克隆你仓库在 GitHub 上的内容**——不是你本地的检出。官方明确：克隆的是当前目录的 GitHub 远程在当前分支的状态，**有本地提交要先推送**；没有远程或未装 Claude GitHub App 时，会把你本地仓库打包上传（有大小与文件类型的限制，敏感文件的未提交修改在 macOS/Linux/WSL 会被排除）；
- **网络**：默认是受限的“Trusted”级别，可在环境配置里调整；
- **环境会过期**：长时间不活动后 VM 被回收。重新打开会话会得到新的 VM：**对话历史恢复；后台运行的 shell 命令、子代理、会话级定时任务不恢复**；
- **在 Desktop 里**：在环境选择器的 **Cloud** 下选择；官方说明 Desktop 可以从 **Open in** 菜单把本地会话的 Code 标签页会话发送到云端；
- **局限**：仓库克隆与 PR 创建要求 GitHub；组织若启用 IP 白名单，Anthropic 托管的云会话会因认证错误而失败。

### 什么时候适合云端

- 任务**长**、**自成一体**、你不想占着电脑；
- 仓库已经在 GitHub 上、分支已推送；
- 你能接受它**只看得到已提交的内容**。

### 什么时候不适合

- 依赖你本机独有的文件、服务或凭据；
- 仓库在 GitHub 之外（不能把结果推回去）；
- 你需要 Browser 窗格里的即时预览。（官方对 Browser 窗格的限制只明确写了 SSH 会话；云端预览的具体能力作者没有读到，**不要假设**。）

## 3. SSH 会话

官方 Desktop 参考（2026-10-26）：

- 连接你自己的机器：服务器、云虚拟机、开发容器。需要先**添加连接**；Desktop 会在首次连接时**自动在远程机器上安装 Claude Code**；
- 文件窗格在 SSH 会话里是**只读**的；**Claude 在 SSH 会话里不能使用 Browser 窗格的工具**；
- **Desktop 断开期间任务可继续**：运行中的任务可以在 Desktop 断开时继续，但在使用 Claude 账号登录的情况下，登录过期会让它停止；断开期间对 worktree 的编辑、受限文件夹的读取等会有等待与失败情形，官方有详细说明；
- 要访问远程机器上的开发服务器（比如 3000 端口），需要自己做端口转发：`ssh -N -L 3000:localhost:3000 <主机>`，然后在本机浏览器打开 `http://localhost:3000`；
- 关于“别在对话进程还运行时对同一会话执行 `claude --resume`”——两个进程会写入同一个对话，官方明确提醒。

**凭据与权限**是 SSH 的主要风险点：远程机器上的 Claude 以**那台机器上的用户**身份运行。你给它多大的权限，就是那个用户有多大。

## 4. 跨端继续：能做什么，不能做什么

官方云端文档（2026-10-26）描述的几条路径：

| 路径 | 方向 | 说明 |
|---|---|---|
| `claude --cloud "任务"`（CLI） | 本地 → **新的**云会话 | 创建新会话；克隆的是 GitHub 上的分支，不是本地未推送内容 |
| `claude --teleport`（CLI） | 云 → 本地终端 | 把云端会话**及其分支**拉到终端；需要干净的 git 状态、同一仓库、分支已推送、同一账号 |
| Desktop **Open in** 菜单 | 本地 Code 会话 → 云端 | 官方说明可以把本地会话发送到云 |
| Remote Control | 从手机/浏览器操作你本机会话 | 会话仍然在你的机器上运行 |

几个**明确不会**发生的事（官方原话大意）：

- 从 CLI 的角度，会话交接是**单向的**：可以拉云会话到终端，不能把已有的终端会话推到云；
- 拉到终端后，终端得到的是**自己的副本**：之后在终端里的新工作**不会**出现在云会话里；
- `--teleport` 与 `--resume` 不同：后者重新打开的是本机的历史，**不会列出云会话**；
- 桌面版与独立 CLI 的会话列表**并不自动互通**。

> **结论：跨端继续靠的是“仓库里的分支”，不是“同一个对话”。** 所以第 12 章的 `HANDOFF.md` 与第 15 章的提交，在跨端时比任何自动同步都更可靠。

## 5. 选择表

| 你的情境 | 倾向 | 理由 |
|---|---|---|
| 学习本书、练习案例 | Local | 文件在手边，Browser 窗格可用 |
| 要改的是机器上独有的东西（本地数据库、特定硬件） | Local 或 SSH | 云端看不到 |
| 长时间、自成一体、已推送到 GitHub | Cloud | 关机也继续 |
| 项目在一台性能强的开发机或容器里 | SSH | 在那里运行与构建 |
| Windows 上要用 Linux 工具链 | WSL | 路径与工具都在 Linux 侧 |

## 6. 动手：只做“认路”，不做新建

因为这些环境依赖你的计划与组织，本章的动手**不要求你创建任何新环境**：

1. 打开 Desktop 的环境选择器，**只读地**记下你看到的选项（Local？Cloud？SSH？WSL？）；
2. 对每个选项，写一句“它的文件在哪”；
3. 选一个你**假想**的任务（比如“给 Lab B 加优先级过滤并推送”），写出你会选哪个环境，列出**前提**（需要推送分支？需要 GitHub 连接？）；
4. 如果你的账号有云端：**这时才**决定要不要尝试一次最小的云任务——而且只对**公开的、无敏感内容**的练习仓库。

## 7. 失败分支

- **云端看不到我的改动**：你没推送。推送是你自己的操作，且对外可见——**先确认你愿意把这些内容放到 GitHub 上**（第 20 章）；
- **teleport 失败**：检查干净的 git 状态、是否在同一仓库的检出里、分支是否已推送、是否同一账号；
- **SSH 预览打不开**：官方明确 Claude 无法在 SSH 会话里用 Browser 窗格；要自己做端口转发再用本机浏览器；
- **云端会话“消失”了**：环境过期。重新打开会话；背景任务需要重新启动。

## 8. 独立练习

为同一个任务（“给 Lab B 加优先级过滤，并让别人能审阅”），写出在 **Local** 与 **Cloud** 下的完整步骤，并标出**你亲自做的有对外影响的动作**（推送、创建 PR）。
